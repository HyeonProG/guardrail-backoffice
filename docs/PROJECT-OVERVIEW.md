# Guardrail 프로젝트 개요

## 1. 프로젝트 한 줄 소개
AI를 활용한 커머스 백오피스 개발 과정에서 발생하는 불안정성과 비일관성을 하네스 엔지니어링으로 통제하여, 안정성과 생산성을 함께 개선하는 프로젝트

## 2. 프로젝트 배경
신입 개발자로 실무를 진행하면서 AI를 활용해 개발 생산성을 높이려 했지만, 실제로는 다음과 같은 문제가 반복적으로 발생했다.

- 같은 프롬프트를 입력해도 결과가 매번 달라졌다.
- 프로젝트 컨벤션을 지키지 않는 코드가 생성되었다.
- 아키텍처 원칙과 폴더 구조를 벗어난 산출물이 나왔다.
- 결과물의 안정성이 낮아 사람이 다시 검토하고 수정해야 했다.
- 결국 AI 활용이 생산성 향상보다 재작업 비용 증가로 이어졌다.

이 프로젝트는 이러한 실무 경험을 바탕으로, AI 산출물을 그대로 신뢰하는 방식이 아니라 검증 가능한 규칙과 승인 절차 안에 편입하는 구조를 만드는 것을 목표로 한다.

## 3. 문제 정의
이 프로젝트가 해결하려는 핵심 문제는 아래와 같다.

1. AI 결과의 일관성이 낮아 재현 가능한 개발 흐름을 만들기 어렵다.
2. 코드와 문서 산출물이 프로젝트 규칙을 자주 벗어난다.
3. AI 결과물의 검증 비용이 높아 생산성이 오히려 떨어진다.
4. 결과를 신뢰할 수 있는 통제 장치가 없어 실무 적용이 어렵다.

즉, 문제의 본질은 AI 자체가 아니라 AI 산출물을 검증 없이 받아들이는 개발 방식에 있다.

## 4. 프로젝트 목표
### 4.1 서비스 목표
커머스 백오피스에서 직원이 상품 정보를 입력하면 상품 이미지는 직접 등록하고, AI는 상품명, 카테고리, 특징 키워드를 바탕으로 상품 설명 문구를 생성한다. 이후 직원이 설명을 검토·수정한 뒤 승인 요청을 올리면 관리자 또는 운영자가 최종 승인 또는 반려하는 흐름을 구현한다.

### 4.2 개발 목표
개발 코드 역시 프로젝트 규칙을 벗어나지 않도록 구조, 컨벤션, 의존 방향, 테스트 기준을 점진적으로 통제할 수 있는 기반을 만든다.

### 4.3 최종 목표
AI 활용 개발의 불안정성을 줄이고, 재작업 비용을 낮춰 결과적으로 생산성을 향상시키는 구조를 설계하고 구현한다.

## 5. 도메인 범위
이 프로젝트의 핵심 도메인은 단순 상품 관리가 아니라 `상품 등록 및 승인 프로세스`이다.

초기 범위는 아래 흐름에 집중한다.

1. 관리자 또는 운영자가 카테고리와 상품 옵션 같은 기준 정보를 먼저 관리한다.
2. 직원이 상품 등록 화면에서 상품명, 카테고리, 선택 항목, 이미지, 설명을 입력한다.
3. 직원이 설명란에 키워드를 입력하고 AI 문구 생성을 실행하면 생성 결과가 현재 설명 필드에 바로 반영된다.
4. 직원이 설명을 직접 수정하거나 그대로 유지한 뒤 승인 요청을 올린다.
5. 상품 상태는 `DRAFT`에서 `PENDING`으로 변경된다.
6. 관리자 또는 운영자가 승인 요청 관리 화면에서 최종 승인 또는 반려한다.
7. 승인된 상품만 승인 완료 상품 목록에 노출된다.

## 6. 주요 사용자
### 직원
- 상품 등록 초안 작성
- AI 설명 생성 요청
- 생성 결과 검토 및 수정
- 최종 승인 요청

### 관리자 / 운영자
- 제출된 상품 검토
- 승인 또는 반려
- 카테고리, 상품 옵션, 사용자 관리

## 7. 핵심 가치
이 프로젝트는 단순히 AI를 사용한 서비스가 아니라, AI 결과를 실무 수준으로 통제 가능한 시스템 안에 넣는 것에 가치를 둔다.

핵심 가치는 다음과 같다.

- AI 결과를 바로 반영하지 않는다.
- 검증 가능한 기준을 먼저 정의한다.
- 승인 절차를 통해 최종 반영을 통제한다.
- 개발 프로세스에도 동일한 통제 철학을 적용한다.

## 8. 기술 방향
현재 확정된 백엔드 기술 스택은 다음과 같다.

- Java 21
- Spring Boot 3.5.13
- Spring Data JPA
- Spring Security
- JWT
- Querydsl
- PostgreSQL

AI 설명 생성 연동은 현재 `Spring AI + OpenAI API` 조합과 `application.yml` 또는 환경 변수 기반 설정 방식을 기준으로 설계한다.

프론트엔드와 추가 인프라 구성은 도메인 및 API 설계 이후 확정한다.

## 9. 하네스 엔지니어링 적용 방향
### 서비스 레벨
- AI 생성 결과를 바로 확정하지 않고 직원 검토를 거친다.
- 직원 승인 요청 이후 관리자와 운영자가 최종 반영 여부를 결정한다.
- 권한에 따라 기준 정보 관리와 승인 권한을 분리한다.

### 개발 레벨
- 구조와 규칙을 문서로 먼저 정의한다.
- 이후 패키지 구조, 코드 작성 방식, 의존 방향, 테스트 기준에 대한 자동 검증으로 확장한다.
- 궁극적으로 빌드, 테스트, CI 단계에서 규칙 위반을 차단하는 구조를 목표로 한다.

## 10. 진행 원칙
이 프로젝트는 구현보다 기준 정의를 먼저 진행한다.

진행 순서는 아래와 같다.

1. 프로젝트 개요와 범위를 문서로 확정한다.
2. 도메인 모델과 패키지 구조를 문서로 정리한다.
3. 문서 기준에 맞춰 코드 구조를 생성한다.
4. 엔티티와 기능 구현을 단계적으로 진행한다.
5. 마지막에 하네스 규칙을 자동화로 연결한다.

## 12. 요약
Guardrail은 AI를 활용한 개발과 서비스 운영에서 발생하는 결과의 불안정성을 줄이기 위해 시작한 프로젝트다.

커머스 백오피스 도메인에서 AI 기반 상품 설명 생성 기능을 설계하되, 생성 결과를 검증과 승인 절차 안에 넣고, 개발 코드 또한 점진적으로 하네스 엔지니어링 관점에서 통제 가능한 구조로 발전시키는 것이 이 프로젝트의 핵심이다.
