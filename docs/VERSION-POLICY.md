# 버전 관리 정책

## 1. 목적
이 문서는 Guardrail 프로젝트의 버전 관리 기준을 정의한다.

이 프로젝트는 배포 운영 문서보다 기능과 구조의 변화 흐름을 관리하는 것을 우선한다.

## 2. 버전 형식
버전은 Semantic Versioning 형식을 따른다.

```text
MAJOR.MINOR.PATCH
```

## 3. 버전 증가 기준
### MAJOR
- 하위 호환이 깨지는 구조 변경
- 핵심 도메인 또는 API 계약을 크게 변경하는 경우

### MINOR
- 새로운 기능 추가
- 새로운 도메인 흐름 추가
- API 또는 기능 범위 확장

### PATCH
- 버그 수정
- 내부 로직 개선
- 문서 수정
- 설정 변경
- 리팩토링

## 4. 운영 방식
- changelog는 `0.1.0`부터 시작한다.
- 별도의 release 문서나 날짜는 작성하지 않는다.
- changelog는 간단하게 유지한다.
- changelog 항목은 `추가`, `수정`, `삭제` 기준으로만 작성한다.

## 5. 관리 원칙
- 변경이 발생하면 가능한 같은 작업 흐름 안에서 `CHANGELOG.md`를 함께 수정한다.
- 새 버전을 시작할 때 상단에 새 버전 섹션을 추가한다.
- 버전 증가는 프로젝트 변경 범위에 맞게 판단한다.

## 6. 예시
```md
## [0.1.0]

### 추가
- `docs/DOMAIN-MODEL.md` 문서 추가
- User 도메인 엔티티 추가

### 수정
- `application.yml` JWT 설정 정리
- 패키지 구조 문서 내용 보완

### 삭제
- 사용하지 않는 테스트 설정 제거
```
